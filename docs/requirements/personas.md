# 使用者人物誌 (Personas)

> 在 user story 中以 `persona-id` 引用。新增 persona 前先看是否能用既有的，避免人物誌膨脹。
> 本應用為**個人本機工具**，所有 persona 都是「自己寫小說的個人」，差別在創作目的、技術熟悉度、隱私需求。

---

## 個人創作者 — 自娛型 (`hobbyist-author`)

**情境**：寫小說純為興趣，沒有出版計畫，可能在自己電腦上累積數十萬字未公開。
**目標**：享受創作過程；用 AI 協助突破寫作瓶頸；保有完整創作自由（題材不受平台政策限制）。
**痛點**：靈感枯竭時卡住、章節間設定漂移、想寫敏感題材時被線上工具拒絕。
**對 AI 的期待**：建議多種劇情走向、潤飾文筆、補感官描寫；願意用地端模型換取創作自由。
**技術熟悉度**：中等。能裝桌面應用、複製貼上 API key；裝地端模型要有人帶（步驟要寫清楚）。
**隱私敏感度**：高。偏好內容只在本機；同步要走自己的 Drive，不接受廠商伺服器。

---

## 個人創作者 — 連載型 (`serial-author`)

**情境**：在連載平台或自架站固定更新，需穩定每週交稿，已累積數十至數百章。
**目標**：穩定產出、跨章維持人物與設定一致、跨書共用世界觀、週更不要爆稿。
**痛點**：章數一多 AI 會「忘記」前文；潤稿時不小心改掉伏筆；外包編輯成本高。
**對 AI 的期待**：精準的章節續寫、嚴謹的連貫性檢查、可精簡為短摘要的故事 / 人物狀態。
**技術熟悉度**：中高。能配置多家 API key、會用 git 管理底稿、能跑地端推論。
**隱私敏感度**：中。已發表內容不敏感，但**未發表的後續章節**絕不上雲端廠商。願意用 Google Drive 同步自己的工作機。

---

## 個人創作者 — 構思型 (`worldbuilder-author`)

**情境**：花大量時間建構世界觀、人物群像、設定百科，故事文本反而是後段產物。
**目標**：用 AI 協助發想、整理、檢查設定；產出可作為小說素材的角色卡與場景卡。
**痛點**：腦中設定龐雜、寫成文字時分散；AI 容易給出與既有設定矛盾的細節。
**對 AI 的期待**：根據既有設定推導新細節、為設定矛盾警示、命名（角色 / 地名 / 招式）多方案。
**技術熟悉度**：中等。樂於編輯 markdown、會用標籤與索引。
**隱私敏感度**：中。

## 跨 persona 共通假設

依 [PM 釐清 Q1 + Q2](../architecture/adr/0001-storage-strategy.md)：

- 全部都是**單機**使用，無內建帳號系統，無線上協作
- 全部都接受「**首次啟動顯示警語**，往後不再出現」的內容警告流程
- 全部都期待**模型可選**（雲端 / 地端切換），且可在 Agent / Skill 層級指定不同模型
- 全部都期待 Agent / Skill **可由使用者自行擴充編輯**（不只是廠商出貨）
