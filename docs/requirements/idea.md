這是一個主要寫小說用的 AI Agent 應用程式，採用里程碑式開發，每個里程碑開發結束後，需要進行測試與發佈程序。
測試: 單元測試、回歸測試、BDD 測試
發布程序: 檢視並修改文件，尤其 Readme 與使用者手冊

## 功能描述
1. 核心為利用 LLM 模型協助使用者撰寫色情小說 (也可寫其他小說)
2. 使用者必須提供故事大綱，人物描寫與人物關係，故事背景，寫作風格與額外寫作需求給 AI 產生故事。
## 創作者工作流程如下
	1. 使用者撰寫故事大綱、人物關係、預計章節長度、寫作方式與風格
	2. AI 生成章節大綱與寫作計畫，使用者同意後進行撰寫工作
	3. 開始逐章撰寫故事，每章結束輸出在畫面上，使用者可以在畫面上進行共同編輯或是AI潤飾。
		1. 章節撰寫過程，使用者，可以回復編輯動作，以免誤刪或是誤動作
		2. 使用者可以決定儲存此版本
		3. 使用者可以決定採用目前版本，畫面須提示確認
		4. 使用者同意採用後，進入故事更新動作
	4. 故事更新動作，主要目的為更新故事背景、人物關係，寫作進度，供後續寫作使用
		1. 將章節內容移入前文
		2. 將重要情節演進與人物關係更新到對應的畫面內容，將重要的情節演進和人物關係寫進 Story_status.md 與 Character_status.md 之中
		3. 讀取下一個章節大綱，準備開始寫作
## 故事撰寫採用多 Agent 方式進行，每個 Agent  可以指定 AI 模型(地端或遠端)
	1. 使用可編輯的定義檔，可以定義每個 agent 採用哪種模型，
	2. 根據故事大綱(synopsis.md)產生章節大綱 (chapter.md) ，使用者可以命令  AI 產生章節大綱，也可以自行撰寫，或是先用 AI 產生後修改。每章的大綱內容可以在後續生成章節內容時修改。
	3. 人物整體關係與描述存在(Character.md)之中，
	4. 根據章節大綱 (chapter.md, character_status.md , story_status.md ) 產生故事，每次讀取一章
	5. 根據章節內容產生章節標題
	6. 根據章節內容更新故事狀態與人物關係狀態 (Story_status.md, Character_status.md)，把必要的劇情演進和人物關係變化寫進故事狀態與人物狀態，提供續寫與故事演進參考，以免 AI 在撰寫後續章節時喪失記憶。Story status 與 Character status 需要精簡，以免佔用過多 context size. 
	7. 需要提供章節續寫功能，避免文章割裂的狀況。
	8. 章節內容產生之後，使用者可以選取部分故事內容，進行潤飾，潤飾若不滿意可以回復。 
	9. 章節內容在編輯過程中，有 (Undo, Redo)功能。
	10. 確認章節內容符合使用者需求後，存檔進 chapter_####\_{Chapter_title}.md 檔案，同時把該章節的產生提示詞(包含寫作風格，章節大綱，人物關係與額外寫作需求等)一併寫入 chapter\_####\_prompt.md 供日後修改使用. #### 為四碼數字，不足位數須補 0 。
## 使用者介面與模組
	1. 使用 Web 開發，本地運行(是否有比 Electron 更好的架構?)，採用 API First 方式開發。
	2. 有故事發想模組 (Optional)
	3. 有章節寫作模組 (預設畫面)
	4. 有人物創作模組，人物製作包含輸入圖片，使用 VL 輸出人物外貌。輸入人物年齡性別，個性 (MBTI 人格特質)，星座，身高體重，血型, 三圍等。最後彙整成文字。使用 AI 輸出人物個性。
	5. 有故事場景創作模組，可以挑選常見場景，包含時代(如古代、現代，未來)、背景(仙俠、武俠、宮廷、家庭等) , 可以提供寫作背景參考，以免故事中出現不適合的對話與場景(如在宋朝故事中輸出現代道具，譬如手機)。
	6. 有編輯審稿模式，可以根據故事背景進行文件內容建議。審稿的 Skill  可以由使用者進行編輯，但提供標準系統審稿 Skill 給使用者。
	7. 人物創作模組、故事場景模組與編輯模組都是可以勾選的創作流程，可以使用 Agent 或是 Skill 的方式進行。
