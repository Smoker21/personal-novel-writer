# TC-04 指令與格式遵循

> 對應 spec：多處（status 是 Markdown、潤飾類 Skill 要求只回變換結果、tool-use 場景需 JSON）
> 推薦溫度：0.2

## 目的

驗證模型在「明確要求格式」時的服從度。實作中很多 Agent 要求 JSON 輸出（structured output 走 schema validation），Skill 要求「只回變換後文字」——若模型常常加廢話，需要 retry 或大幅後處理，影響整個系統可靠度。

## 子測 4-1：JSON 輸出

### System prompt

```
你是文字分析助手。請只回傳 JSON 物件，不要加 markdown code fence、不要加說明文字。

格式：
{
  "wordCount": <number>,
  "characters": [<string>...],   // 出場的人物姓名陣列
  "mood": "<string>"             // 一個詞的氛圍標籤
}
```

### User prompt

```
分析這段文字：

「蘇晴推開言字書店的木門時，雨剛好停了。林書言站在木桌後翻著一本舊筆記本，沒有抬頭。」
```

### Pass 條件

- 回傳純 JSON（首字 `{` 末字 `}`），可被 `JSON.parse` 直接吃下
- `characters` 陣列恰好 `["蘇晴", "林書言"]`（順序不重要）
- 沒有 markdown code fence
- 沒有「以下是分析結果」之類的廢話前綴

### 評分

| 維度 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|
| 純 JSON 可解析 | 含 markdown / 廢話無法解析 | 含 fence 但去掉 fence 後可解 | 純可解析 JSON |
| 欄位正確 | 缺欄位或型別錯 | 全欄位但 mood 過長 | 全欄位且型別正確 |
| 角色辨識 | 漏 / 多 | 全對 | 全對且大小寫一致 |

## 子測 4-2：「只輸出變換結果」

### System prompt

```
你是文字潤飾助手。我會給你一段中文，請改寫得更含蓄一些（避免過於直白的形容詞），保持原意與字數相當。

只輸出改寫後的文字，不要解釋、不要加引號、不要加 markdown 格式。
```

### User prompt

```
她非常非常喜歡他，看到他就忍不住露出超開心的笑容。
```

### Pass 條件

- 不含「以下是改寫」「希望這樣可以」等廢話
- 不加引號 / code fence / markdown
- 字數與原文相近（誤差 ±30%）
- 確實有改寫（不是 echo 原文）

### 評分

| 維度 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|
| 純文字無雜訊 | 帶解釋 / 引號 / fence | 有少量解釋 | 純改寫文字 |
| 改寫有效 | 與原文一致 | 改寫但仍直白 | 確實更含蓄 |
| 字數合規 | 嚴重偏離 | 略偏 | 相當 |

## 子測 4-3：拒絕加 Author's note

### System prompt

```
你是中文小說章節寫手。寫一段約 100 字的場景。

只輸出正文，禁止：
- 加摘要 / Author's note
- 加章節標題（除非我提供）
- 加任何解釋
```

### User prompt

```
場景：黃昏，蘇晴獨自走在書店外的巷子，回想剛才看到的筆記本內容。
```

### Pass 條件

- 整段純正文
- 沒有 `## 摘要` `(Author's note: ...)` 等附加區塊

### 評分

| 維度 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|
| 無 Author's note / 摘要 | 加多餘區塊 | 加單行 | 純正文 |

## TC-04 總分

三個子測各自加總後取平均。Pass 條件：每個子測都 Pass。
