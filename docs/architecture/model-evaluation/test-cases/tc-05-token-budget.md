# TC-05 Token 上限服從

> 對應 spec：[007 status-updater](../../specs/007-update-story-character-status.md) token 上限規則
> 推薦溫度：0.5

## 目的

`status-updater` 的精簡重試流程設計依賴一個假設——當系統提示說「不超過 N 字」時，模型會努力服從。如果模型完全不在乎字數要求，spec 007 的「自動精簡重試」就只能依賴「強制截短」這條退路，狀態品質會劣化。

## System prompt

```
你是小說的故事狀態維護員。我會給你一段章節原文。請產出 story_status，記下這章發生的關鍵劇情。

**字數限制：總字數不可超過 150 個中文字。** 這是硬限制，超過就會被截斷。

只輸出狀態文字，不要解釋。
```

## User prompt

```
章節原文：

蘇晴第一次走進言字書店是六月的午後。雨在她踏上騎樓那刻潑下來，她回頭看了一眼街道，索性把傘收進門邊的傘架。

書店比她從外頭看的要深，書架排列像迷宮。她沿著「文學．日本」的書脊慢慢走到店尾，看見一張木桌與桌後的男人。男人約莫近三十，戴著一副舊式的圓框眼鏡，正在翻一本封面磨得發白的筆記本。

「不好意思，雨太大了，我借避一下。」

「沒關係。」男人抬起頭，「想喝點什麼嗎？我這裡只有便宜的茶。」

蘇晴點了頭。等對方倒茶時，她看到桌上那本筆記本攤開的某一頁，是用鋼筆寫的字跡，淡藍色，工整中帶點顫抖。她認出那個地址——是她母親二十年前住過的巷子。

「這是誰的？」她問。

男人遞茶過來。「客人不要的，我撿來看。看完會丟。」他自我介紹叫林書言，這書店是兩年前盤下來的。

「能借我看一下嗎？」她忽然這樣問。

「妳要看完都行。」林書言把筆記本推過去，「不過得在店裡看。我捨不得它跑出去。」
```

## 評分維度

| 維度 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|
| 字數服從 | > 250 字（嚴重超量） | 150~200 字（小幅超出） | ≤ 150 字 |
| 關鍵保留 | 漏掉「筆記本」或「母親地址」 | 抓到主軸但丟細節 | 在字數內仍涵蓋全部關鍵 |
| 沒灌水 | 大量原文搬 | 重述但有水分 | 全部濃縮重寫 |

## Pass 條件

三個維度均 ≥ 3。**字數服從**必 ≥ 4（這是這個 case 主測項）。

## 進階觀察：多次跑同樣提示，輸出穩定嗎？

跑 3 次（同樣輸入、同 temperature 0.5）：

- Run 1 字數：___，Pass？
- Run 2 字數：___，Pass？
- Run 3 字數：___，Pass？

3 次都 Pass = 模型對字數要求是穩定的；只有 1 次 Pass = 不穩定，spec 007 的「精簡重試」可能要常觸發。

## 紅旗

- 直接回原文（沒精簡）
- 字數超過 1.5 倍上限（225 字以上）—— 表示模型對「字數」這個概念無感
