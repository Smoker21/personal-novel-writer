# TC-02 狀態提煉

> 對應 spec：[007 status-updater](../../specs/007-update-story-character-status.md)
> 對應規定：「精簡寫進 story_status.md 與 character_status.md」「token 上限 1500」
> 推薦溫度：0.5（不要太發散）

## 目的

驗證模型能否從章節原文中**提煉關鍵劇情演進與人物關係變化**，並寫出符合上限的精簡狀態。這是記憶機制的引擎；做不到的話跨章節記憶就會壞。

## System prompt

```
你是小說的故事狀態維護員。我會給你：
1. 既有的 story_status.md 與 character_status.md（可能為空）
2. 剛採用的章節原文
3. 出場角色清單

任務：產出**新版**的 story_status.md 與 character_status.md，使下一章撰寫時 AI 仍記得本章發生什麼。

嚴格規則：
1. story_status.md 不超過 1500 中文字。
2. character_status.md 不超過 2000 中文字。
3. 不新增未在輸入中出現的角色姓名。
4. 不修改既有角色姓名的任一字元。
5. 已記錄的關鍵劇情若仍重要必須保留；不重要的可以省略合併。
6. 輸出格式：兩個 Markdown 區塊，分別以 `## story_status.md` 與 `## character_status.md` 為標題。
7. 不要解釋你做了什麼。
```

## User prompt

```
## 既有 story_status.md
（空白；本章為第一章）

## 既有 character_status.md
（空白）

## 出場角色
- 蘇晴（30 歲女作家，溫和敏感）
- 林書言（28 歲書店老闆，健談）

## 本章原文（第一章「梅雨初晴」）

蘇晴第一次走進言字書店是六月的午後。雨在她踏上騎樓那刻潑下來，她回頭看了一眼街道，索性把傘收進門邊的傘架。

書店比她從外頭看的要深，書架排列像迷宮。她沿著「文學．日本」的書脊慢慢走到店尾，看見一張木桌與桌後的男人。男人約莫近三十，戴著一副舊式的圓框眼鏡，正在翻一本封面磨得發白的筆記本。

「不好意思，雨太大了，我借避一下。」

「沒關係。」男人抬起頭，「想喝點什麼嗎？我這裡只有便宜的茶。」

蘇晴點了頭。等對方倒茶時，她看到桌上那本筆記本攤開的某一頁，是用鋼筆寫的字跡，淡藍色，工整中帶點顫抖。她認出那個地址——是她母親二十年前住過的巷子。

「這是誰的？」她問。

男人遞茶過來。「客人不要的，我撿來看。看完會丟。」他自我介紹叫林書言，這書店是兩年前盤下來的。

「能借我看一下嗎？」她忽然這樣問。

「妳要看完都行。」林書言把筆記本推過去，「不過得在店裡看。我捨不得它跑出去。」

雨在外面下得密。她坐在木桌邊翻那本筆記本，茶在她手邊涼下來。林書言沒有再說話，只在她翻到某頁停太久時，輕輕咳了一下，又埋回他自己手裡的另一本書。

雨停的時候，她已經知道自己會再來。

請依規則產出兩份 status。
```

## 評分維度

| 維度 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|
| 關鍵劇情捕捉 | 漏掉「筆記本」「母親地址」等關鍵 | 抓到主軸但漏細節 | 涵蓋人物相遇、筆記本、地址巧合等所有關鍵 |
| 字數服從 | 任一檔超過上限 | 在上限內但用盡（緊繃） | 在上限內且仍有 30% 餘裕 |
| 格式遵循 | 沒有兩個 Markdown 區塊 | 有但 heading 寫錯 | 完全符合 `## story_status.md` / `## character_status.md` |
| 角色一致性 | 出現新角色 / 改字 | 沒新增但屬性走樣 | 完全保持輸入中的姓名與設定 |
| 精簡感 | 大段抄章節原文 | 部分濃縮、部分原句搬 | 全部用提煉式語言重寫 |

## Pass 條件

5 個維度均 ≥ 3 分。

## 紅旗

- 直接抄章節原文當 status（沒提煉）
- 改寫情節（例：把「她借避雨」改成「她跑來找他」）
- 補充原文沒有的劇情（幻覺）
