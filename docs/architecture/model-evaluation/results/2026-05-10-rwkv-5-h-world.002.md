### 🚨 致命問題：chat 端點讓模型以為要對話而非續寫

**症狀**：跑 TC-03（章節撰寫）與 TC-07 default（context 利用率），RWKV-Runner OAI-compat `chat/completions` 端點讓模型只回了 **9 ~ 16 tokens**，且內容是：

- TC-03：「請問需要什麼樣的寫作指導呢？」
- TC-07 default：「可以幫你一起寫。」

模型把任務當成了「使用者來諮詢」而非「寫章節」。原因是 RWKV-Runner 把 `messages: [system, user]` 內部串成偽 chat template，RWKV-5 World 系列被觸發成「客服模式」。

**修法（強制）**：

1. **任何要求模型「續寫長文」（chapter-writer / 撰寫類 Skill）的呼叫，必須走 `/v1/completions` 端點，不要走 `/v1/chat/completions`**
2. Prompt 必須手刻成 RWKV World 訓練格式：
   ```
   User: <把 system + user 內容拼起來，明確說「請直接開始寫」>

   Assistant:  <- 注意末尾留空白
   ```
3. 帶 `stop=["\n\nUser:", "\n\nHuman:"]`，避免模型自問自答
4. `packages/llm-adapter/src/providers/rwkv-runner.ts` 必須提供 `complete()` 與 `chat()` 兩個 API；router 為 RWKV provider 路由「長文續寫」類 task 一律走 complete

短指令類（潤飾、JSON 抽取、status 提煉）`chat/completions` 暫時可用，但仍建議實測。

### 🚨 字數限制無效

TC-05 三次 rerun 字數：**396 / 497 / 475**（限制 150）。模型完全無視「不可超過 N 字」。

- `status-updater` spec 007 的「自動精簡重試」**必須** fallback 到強制截短（生成後切片），不能依賴模型自我約束
- 在 prompt 中強調「**硬限制**」「超過會被截斷」對 RWKV 無效
- 應用層需要實作：生成後字數檢查 → 超過 → 重試 N 次 → 仍超過 → 強制 `slice(0, N)` 並補一句「（已截斷）」

### 🚨 簡體漂移

TC-08 8-1 整段輸出變成簡體（「双方都应」「男方试图」「女方立即」）。雖然 system prompt 已要求「中文」，沒明示「繁體中文」就會跑掉。

- **所有 prompt 必須在 system 開頭與 user 末尾各放一次「請以繁體中文回應」** — RWKV 對 prompt 末尾敏感度高，光放開頭不夠
- `packages/prompt-library/` 應提供 `tradChinesePrefix` / `tradChineseSuffix` 兩個常數，組 prompt 時夾住 user content
- 實作層應加入後處理偵測：output 若簡體比例 > 0.5%，記 warning（`tools/eval/src/scoring/rules/traditional-chinese.ts` 已有 detector，可直接 reuse 進 adapter 的 `quality_check`）

### 🚨 角色服從不可信，需要在應用層擋

TC-01 模型自由發揮塞了「程系上、謝謝誇、方便敘」這類無關內容，TC-08 8-2 直接生出「趙立志」「小語」兩個新角色。

- chapter-writer 寫完一定要跑 `continuity-checker`（auto post-step），偵測到新姓名候選 ≥ 2 → 退回重寫或人工確認
- 評分工具的 `name-presence.ts` 規則可以直接搬到 adapter 的 `validate()` 階段
- 不能假設 prompt 規則「只能用清單內姓名」會被遵守

### 🚨 大量重複 / 自我引用

TC-01 / TC-04 觀察到「第二段:... 第二段:...」「就在此時,一隻黃鶯從樹上飛過.就在此時,一隻黃鶯從樹上飛過.」整句重複。

- presence_penalty=0.4 / frequency_penalty=0.4（runtime guide 建議值）**仍然不夠**
- 對於長輸出（max_tokens > 1000），考慮把 frequency_penalty 提到 0.6，或在後處理偵測「同一句出現 2+ 次 → 截斷或重試」

## Architecture-specific observations

- **架構類別**：RNN (RWKV-5 v5.2)，32+1 層
- **長 context 行為**：
  - **TC-07 兩變體都提到「照片」** — 對此 prompt 長度（~800 token user prompt），記憶衰減**不致命**
  - 但兩變體都漏掉「林書言提議幫忙問老鄰居」（outline 規定的次要情節）— outline 中段細節仍可能丟失
  - **TC-02 章節原文長**（~600 字）→ 模型仍捕捉到主要事件（避雨、筆記本、地址巧合），但**輸出格式完全錯誤**（沒有 `## story_status.md` heading），疑似 chat 端點干擾
- **Prompt format 敏感度**：
  - **`chat/completions` 端點對「續寫類任務」會誤觸發對話模式**（TC-03 / TC-07 default 各只回 9-16 tokens 的客服式回答）— 詳見〈致命問題〉
  - 短指令類（TC-04 / TC-06 / TC-08）chat 端點可用
  - 結論：**長文續寫一律走 `/v1/completions` 並手刻 `User:\n...\n\nAssistant: ` 格式**
- **採樣參數對品質的影響**：
  - 維持 runtime guide 建議值（creative T=1.0/top_p=0.6/penalty=0.4；instruct T=0.5/top_p=0.5/penalty=0.6）整體可用
  - 但**仍觀察到大量重複句**（TC-01 / TC-04），penalty 0.4 對長輸出不夠 → 建議 max_tokens > 1000 時 frequency_penalty 提到 0.6
  - 未實測降溫至 0.7 的效果（後續可加 sweep）
- **與 Qwen3.5-35B-A3B IQ4_XS 的比較**：尚未跑（result 檔仍待跑）。本評估後再做 side-by-side

### 已知的提示詞工程注意事項

> 已從 2026-05-10 實測驗證；逐條搬進 `docs/agents/<name>.md` 與 `packages/prompt-library/`：

1. **強制繁體**：所有 system prompt 開頭與 user prompt 末尾各放一次「請以繁體中文回應」。光放開頭不夠（TC-08 8-1 漂簡體實測）。
2. **長文續寫不走 chat 端點**：`chapter-writer` 與所有「請寫一段 N 字 ...」類 prompt 必須走 `/v1/completions`，手刻 `User: ...\n\nAssistant: ` 並帶 `stop=["\n\nUser:"]`。chat 端點觸發客服模式（TC-03 / TC-07 default 實測）。
3. **格式 / 字數要求複寫到末尾**：RWKV 對 user prompt 末尾敏感度高。例：TC-07 把「請特別注意：本章必須提到照片」放末尾後兩變體都記得照片（vs 只放中段時 default 變體可能漏）。
4. **字數限制不可信賴**：應用層必加生成後 word-count check + 強制截短。TC-05 三次 rerun 都超出限制 2-3 倍。
5. **角色清單防呆**：寫完一定要跑 name-presence 檢查（從 `tools/eval/src/scoring/rules/name-presence.ts` 搬規則進 adapter），偵測新角色 ≥ 2 → 退回。模型不會自我約束（TC-08 8-2 生出「趙立志」「小語」）。
6. **JSON 輸出**：TC-04 4-1 chat 端點失敗（不可解析）。若需要 structured output，要嘛切 completions 端點，要嘛換 Qwen 等 Transformer。
7. **重複句檢測**：長輸出（max_tokens > 1000）後處理檢查「同句重複 ≥ 2 次」→ 截斷或重試。frequency_penalty 0.4 不夠抑制（TC-01「就在此時,一隻黃鶯從樹上飛過.」整句重複實測）。

### LLM adapter 的影響

依 2026-05-10 實測，[ADR-0004](../../adr/0004-llm-adapter.md) **必須**補（不再是 nice-to-have）：

- [x] **per-provider sampling override**（已在 `tools/eval/src/config.ts` 驗證可行；adapter 照搬即可）
- [ ] **RWKV provider 必須提供雙端點：`chat()` + `complete()`**。長文續寫類任務 router 要強制走 `complete()`，避免 chat 端點觸發客服模式
- [ ] **prompt template helper**：`packages/prompt-library/` 提供 `buildRwkvCompletionPrompt(systemPrompt, userPrompt)` 把兩段串成 `User: ...\n\nAssistant: ` 並補 stop tokens

- [ ] **post-generation validators**（共用 module）：
  - `wordCountWithin(min, max)` → 超出 → 重試 N 次 → 強制截短

  - `noNewCharacters(allowedNames[])` → 偵測新姓名 → 退回
  - `noRepeatedSentences(threshold)` → 偵測重複句 → 截斷重試
